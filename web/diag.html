握手耗时—
  • 能打开这个页面 = HTTP 转发是通的；要查的只剩 WebSocket 升级那一段。
  • QNAP / 威联通「反向代理」：把目标协议从 HTTP 改成 HTTP 和 WebSocket（源协议保持 HTTP，目标仍是 NAS 的 6080 端口）。 两端都留纯 HTTP 时 Upgrade 头会被吃掉。
  • nginx：proxy_http_version 1.1 + proxy_set_header Upgrade $http_upgrade + proxy_set_header Connection $connection_upgrade，并关掉 proxy_buffering。
  • 群晖 DSM：反向代理 → 编辑 → 自定义标题 → 点「WebSocket」自动补两条头。
  • Cloudflare：橙云支持 WebSocket，但只监听固定端口（443 / 2053 / 2083 / 2087 / 2096 / 8443）；非这些端口要用 Tunnel 映射。
  • 路径前缀：反代若把路径改写成 /115nas/xxx，需要在反代侧 同时透传该前缀，容器本身不再需要 WS_PATH（KasmVNC 固定用 websockify，相对本页解析）。
  • 命令行自检（在能访问本页的机器上跑）： curl -i -N --noproxy '*' -H "Connection: Upgrade" -H "Upgrade: websocket" -H "Sec-WebSocket-Version: 13" -H "Sec-WebSocket-Key: x3JJHMbDL1EzLkh9GBhXDw==" -H "Origin: <本页地址>" -H "Sec-WebSocket-Protocol: binary" <本页地址>websockify 必须返回 HTTP/1.1 101。 Origin 和 Sec-WebSocket-Protocol 这两个头都不能省——KasmVNC 的握手解析 缺任一就按非法请求拒掉，返回 404；那是命令本身不完整，不代表链路不通。 --noproxy '*' 同样不能省，否则本机代理会吃掉升级头，也是假阴性。
  • 实在绕不过去：用 TCP 层映射（路由器端口转发 / frp type=tcp） 直接指向容器 6080，HTTP 与 WS 一起透传。
